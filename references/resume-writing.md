# Resume Writing Reference

Use this reference when optimizing Chinese resumes, tailoring to a JD, or turning raw project notes into credible application material.

## Content Principles

- Keep facts verifiable. Rewrite weak wording, but do not invent employers, dates, awards, tools, metrics, or production impact.
- Put the target role first. The strongest sections should match the JD's required skills, domain, workflow, and responsibility level.
- Prefer concise achievement bullets over self-evaluation adjectives.
- Use Chinese resume rhythm: short clauses, strong verbs, clear technology nouns, and direct evidence.
- Avoid empty claims such as "学习能力强" unless paired with proof.

## ATS and Structure

- Use conventional section titles: 个人优势、核心技能、工作经历、重点项目、校园/个人项目、竞赛/荣誉、教育背景、自我评价.
- Keep dates, company names, job titles, schools, degrees, majors, and project names in text, not only images.
- Use real text bullets in DOCX and HTML. Avoid screenshots as the main resume body.
- Keep contact information easy to copy. For public HTML, mask sensitive details unless approved.
- Avoid complex tables for core content; many ATS parsers handle simple headings and bullets better.

## JD Tailoring

1. Extract the JD's hard requirements: role title, required skills, domain, tools, years, education, and deliverables.
2. Map resume evidence to those requirements.
3. Reorder sections and bullets so the strongest matching evidence appears first.
4. Rewrite bullets using the JD's terminology only when the candidate genuinely has that experience.
5. Remove or compress unrelated content that steals page budget.

## STAR Bullet Pattern

Use this compact pattern for project and work bullets:

`场景/目标 + 行动/技术 + 结果/交付`

Good Chinese forms:

- `围绕<业务/设备目标>，负责<模块/任务>，完成<交付物/效果>。`
- `基于<技术栈>实现<功能>，支撑<测试/联调/上线/维护>。`
- `将<现场反馈/用户问题>拆解为<任务>，推动<验证/迭代/交付>。`

If no metric exists, use concrete non-numeric outcomes such as `完成样机验证`、`支撑联调`、`降低沟通成本`、`形成测试闭环`.

## Early-Career Chinese Resume Defaults

- Lead with 2-4 lines of 个人优势 tailored to the target role.
- Keep 核心技能 grouped by capability, not a long comma pile.
- For projects, show role, stack, responsibility, and delivery outcome.
- Put education after experience/projects unless the school or degree is the key selling point.
- Keep self-evaluation short or remove it if page space is tight.

## Red Flags to Fix

- Responsibilities are vague: `参与项目开发` without module or deliverable.
- Bullets list technologies without explaining what the candidate did.
- Claims are too large for the experience level.
- One project repeats the same bullet style three times.
- The resume is visually polished but the text does not match the target role.
